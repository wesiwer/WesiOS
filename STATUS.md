## Сессия 2 — продвинутый прогноз, аудит Treasury/Sandbox/кошелька

Запрос пользователя: разобрать систему прогноза и сделать её максимально
точной; проверить Wesi Treasury и «кошелёк» (Home) на логические и визуальные
баги; всё, что чинится в Treasury, зеркалить в Sandbox (идентичное поведение,
изолированные данные); везде поднять версию приложения.

### Новый движок прогноза — настоящий bootstrap Monte-Carlo

Старый `generateForecast` был **не тем, чем себя называл**: комментарий в коде
гласил «non-linear, Monte-Carlo inspired», но по факту это было одно случайное
блуждание с `Random(42)` и аналитической нормальной шириной полосы
(`p50 ± 1.28×spread`) — не симуляция путей, а формула.

Новые файлы (`lib/features/treasury/services/`):

| Файл | Что делает |
|---|---|
| `forecast_engine.dart` | `ForecastEngine.generate(...)` — общий для Treasury и Sandbox. Разделяет историю на детерминированные регулярные платежи (проецируются по датам) и «шум»; считает сезонность по дню недели, EWMA-тренд (полураспад 10 дней, устойчивее плоского окна), bootstrap-семплирование реальных остатков (сохраняет асимметрию расходов, не нормальное распределение); аномалии исключены из фонового шума, но участвуют как риск редкого «шока» с исторической частотой. Запускает 1000 траекторий и считает P10/P50/P90 **эмпирически** по итогам симуляции, а не по формуле. Возвращает `ForecastResult` с диагностикой (сколько дней истории, сколько путей, учтена ли сезонность). |
| `anomaly_engine.dart` | Детекция аномалий на MAD (median absolute deviation) вместо обычного z-score — старый метод считал stdDev по тем же выбросам, которые искал (эффект маскировки: один гигантский расход раздувал stdDev настолько, что переставал быть аномалией по собственной метрике). Порог modified z-score 3.5 — стандартная рекомендация (Iglewicz & Hoaglin). |
| `recurring_engine.dart` | Общая логика регулярных платежей: проекция будущих начислений по датам (с клампом на короткие месяцы/29 февраля) + исправленная due-проверка (см. баг ниже). |

`TreasuryService`/`SandboxService` теперь **делегируют** в эти движки вместо
собственных копий алгоритма — гарантирует идентичное поведение (запрос
пользователя), при этом данные остаются в разных Hive-боксах (изоляция).
Юнит-тесты: `test/treasury_engines_test.dart` (9 тестов — детерминированность
при отсутствии шума, упорядоченность перцентилей, клампы дат, регресс-тест на
баг due-даты, MAD-детекция).

### Дополнения к прогнозу (тот же запрос — «максимально точный»)

- Регулярные платежи (зарплата, подписки) теперь **явно проецируются** на будущие дни по датам, а не размываются в общем шуме — статистически корректнее.
- 4-й режим графика — «Тепловая карта» (сезонность по дню недели, bar-график Пн–Вс) — прямой побочный продукт нового движка, использует существовавший, но ранее неприменённый локальный ключ `weekly_activity_heatmap`.
- Диагностика прямо на экране: «На основе N дн. истории · M симуляций Монте-Карло · с учётом дня недели / мало истории для сезонности» — прозрачность вместо слепого доверия к цифрам.
- Экран честно показывает «Недостаточно данных для прогноза» при <3 транзакциях вместо прежнего пустого/непонятного состояния.
- Видимое окно истории на графике теперь масштабируется с горизонтом прогноза (`clamp(30, 90)`) — 90-дневный прогноз получает пропорциональный контекст истории, а не всегда фиксированные 30 дней.

## Архитектура (не баги)

1. `SandboxService` ≠ `TreasuryService` — **намеренное** дублирование на уровне сервиса/хранилища (разные Hive-боксы, разные классы). Статистика (прогноз/аномалии/регулярные платежи) при этом идёт через ОБЩИЕ движки в `lib/features/treasury/services/{forecast,anomaly,recurring}_engine.dart` — так гарантируется идентичное поведение без ручного дублирования кода. Не разводи эти движки обратно по двум сервисам — именно это создавало баги-расхождения (пример: `processRecurringPayments` был только в Treasury).
2. Суммы внутри в RUB-эквиваленте; UI через `CurrencyService.fromRub` / `toRub`.
3. Кастомный title bar (`TitleBarStyle.hidden` + `WindowControls`).
4. Курсы: `ExchangeRateService` → cbr.ru (`scripts/XML_daily.asp`); fallback — exchangerate.host, затем зашитые курсы. Парсер проверен на живом ответе ЦБ от 28.07.2026: разбираются все 54 блока `<Valute>`, все восемь валют приложения присутствуют (USD 78,02 · EUR 88,76 · GBP 103,97 · CNY 11,52 · UAH 1,74 · BYN 27,06 · KZT 0,164).
5. **CI пересоздаёт `windows/`.** Шаг «Wipe broken Windows platform stub» удаляет всю папку и заново генерирует её через `flutter create`, потому что в репозитории лежит неполный огрызок (нет `flutter_window.cpp`, `win32_window.cpp`, `utils.cpp`, `Runner.rc`). Любая правка в `windows/runner/` **в сборку не попадает** — переживает только то, что workflow восстанавливает отдельным шагом (сейчас это иконка). Не чини нативные баги правками в `windows/` — они не доедут.
6. `SetQuitOnClose` должен быть `true`. При `false` `WM_DESTROY` не вызывает `PostQuitMessage`, и после закрытия окна процесс остаётся жить.
7. `lib/core/services/finance_firestore_service.dart` — мёртвый код, исключён из анализа: `cloud_firestore` / `firebase_auth` убраны из pubspec (ломают Windows desktop build), файл ниоткуда не импортируется.
8. Калькулятор — глобальный оверлей в `app.dart` (`CalculatorOverlay`), не route. Закреплённый переживает смену вкладок и не перехватывает клики.
9. `android/app/src/main/res/` отсутствовал в репозитории целиком, хотя `AndroidManifest.xml` всегда ссылался на `@mipmap/ic_launcher`, `@style/LaunchTheme`, `@style/NormalTheme`. Сборка падала на `:app:processReleaseResources` — этого не было видно, потому что раньше билд умирал ещё на компиляции Dart. Ресурсы добавлены; иконки отрисованы из `assets/images/app_icon.png`, launch-тема тёмная под `#09090B`.
