# Wesi AI — Chat Interaction Specification

**Статус:** обязательное нормативное дополнение к `docs/WESI_AI_MASTER_SPEC.md`.  
**Дата фиксации:** 2026-08-15.  
**Область:** обычный текстовый чат Wesi AI, интерфейс диалога и поведение пользовательских turn'ов.

## 1. Непрерываемая очередь сообщений

Если Wesi AI уже обрабатывает запрос, отправка пользователем нового сообщения **не должна отменять, обрывать, заменять или перезапускать текущую генерацию**.

Обязательное поведение:

- текущий ответ завершается штатно и отображается полностью;
- новое уточнение, дополнение или следующий запрос помещается в FIFO-очередь того чата, из которого он был отправлен;
- после завершения текущего запроса первый элемент очереди запускается автоматически, затем остальные элементы обрабатываются строго по порядку;
- ошибка текущего запроса не уничтожает очередь: после фиксации ошибки следующий ожидающий turn всё равно должен быть обработан;
- queued turn может содержать текст, вложения либо их комбинацию;
- queued turn сохраняет привязку к исходному conversation/project и не должен случайно выполняться в другом чате;
- ожидающие сообщения должны быть явно видимы пользователю в интерфейсе, включая количество элементов очереди и краткий preview;
- нельзя тихо отбрасывать сообщение из-за того, что модель уже отвечает;
- очередь должна иметь разумный защитный лимит, а при его достижении пользователь получает явное сообщение, а введённый текст не должен молча исчезать;
- обычная отправка следующего сообщения не является командой остановки текущего ответа.

Прерывание текущей генерации допускается только отдельным явным действием пользователя `Stop/Cancel`, если такая команда доступна в интерфейсе.

Пример:

```text
Пользователь: Сделай аудит проекта.
Wesi AI: [обрабатывает запрос A]
Пользователь: И отдельно проверь Android build.   -> queue #1
Пользователь: И не забудь Windows installer.      -> queue #2

Порядок выполнения:
A полностью завершается
-> queue #1
-> queue #2
```

## 2. Интерфейс обычного чата

Интерфейс должен сохранять полный функционал Projects, Universal Attachments, камеры, голосового режима, persona handoff и истории чатов, но использовать современную conversation-first компоновку по ранее утверждённому направлению Claude/Grok/Kimi:

- центральный persona-aware empty state;
- компактный верхний bar;
- drawer/sidebar с проектами и чатами;
- быстрый выбор Зейна, Нирваны и Лобби;
- режимы отображения `Классический` и `Думающий`;
- `Думающий` показывает только безопасное резюме обработки, но не скрытую chain-of-thought;
- видимый таймер текущего ответа;
- inline status/tool events;
- follow-up подсказки после ответа;
- округлый composer с attachments/camera/voice/send controls;
- во время генерации composer остаётся доступным для текстовых уточнений и вложений, которые добавляются в очередь;
- pending queue отображается рядом с composer и не подменяет уже выполняющийся ответ.

## 3. Совместимость и безопасность

Редизайн не должен откатывать уже реализованные возможности Wesi AI. В частности запрещено ради нового UI удалять или обходить:

- AI Projects и project context;
- embedded camera;
- Universal Attachments и staged/chunked upload;
- local chat persistence/migrations;
- retry/error states;
- Зейн/Нирвана/Лобби;
- persona handoff;
- Policy/permissions ограничения backend.

Названия режимов моделей в UI должны соответствовать реально доступным backend tier'ам. Нельзя показывать активный режим, который не имеет работающего server/Relay маршрута.
