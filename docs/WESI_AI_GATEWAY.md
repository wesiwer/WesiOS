# Wesi AI Gateway — обязательная серверная граница

## Решение владельца

Все возможности Wesi AI работают только через зарубежный сервер Wesi Inc.
Приложение WesiOS не обращается напрямую к OpenAI, Anthropic, Google,
провайдерам генерации изображений, видео, аудио или любым другим внешним AI
API.

Целевая схема:

```text
WesiOS на устройстве сотрудника
        |
        | HTTPS + токен сотрудника
        v
Wesi AI Gateway на зарубежном сервере
        |
        | серверные API-ключи провайдеров
        v
текстовая / визуальная / видео / аудио модель
        |
        v
Wesi AI Gateway
        |
        v
WesiOS
```

Предлагаемый адрес шлюза:

```text
https://ai.wesi-inc.ru
```

Поддомен должен указывать на зарубежный сервер, а не на российский сервер
PocketBase. Конкретный IP хранится только в DNS и серверной конфигурации.

## Почему это обязательно

1. Ключи внешних AI-провайдеров никогда не попадают на устройства сотрудников.
2. Провайдера и модель можно менять без выпуска новой версии приложения.
3. Один сервер координирует текст, изображения, видео и аудио.
4. Контекст, личности Зейна и Нирваны и политика маршрутизации остаются под
   контролем Wesi Inc.
5. Можно централизованно применять лимиты, аудит, очереди, кэширование,
   фильтрацию и контроль стоимости.
6. Недоступность одного провайдера не требует обновления приложения — шлюз
   переключается на резервный маршрут.

## Разделение серверов

### Российский сервер

Назначение:

- PocketBase;
- учётные записи сотрудников;
- синхронизация WesiOS;
- корпоративные данные;
- портал загрузки приложения;
- артефакты и обновления.

### Зарубежный сервер

Назначение:

- Wesi AI Gateway;
- оркестрация моделей;
- хранение серверных ключей AI-провайдеров;
- очереди генерации изображений, видео и аудио;
- временное хранение результатов до передачи в корпоративное хранилище;
- потоковые ответы и долгие фоновые задания.

## Аутентификация

Приложение предъявляет шлюзу не ключ внешней модели, а короткоживущий токен
WesiOS/Wesi AI, связанный с сотрудником, организацией, устройством и правами.

Запрещено:

- хранить provider API key в Flutter-приложении;
- передавать provider API key через настройки пользователя;
- возвращать provider API key в ответах шлюза;
- писать provider API key, системные инструкции или полный сырой контекст в
  обычные логи.

## Контракт API

Минимальная версия шлюза должна предоставить:

```text
GET    /v1/health
GET    /v1/capabilities
POST   /v1/chat/completions
POST   /v1/media/jobs
GET    /v1/media/jobs/{id}
DELETE /v1/media/jobs/{id}
```

`/v1/chat/completions` сохраняет OpenAI-совместимую форму там, где это
полезно существующему коду, но модель выбирает шлюз. Клиент может передать
требуемую способность и персону, а не секретное имя внешнего провайдера.

Пример:

```json
{
  "conversation_id": "conv_123",
  "persona": "zane",
  "capability": "reasoning",
  "messages": [
    {"role": "user", "content": "Проверь архитектуру"}
  ],
  "stream": true
}
```

Для медиазадач:

```json
{
  "conversation_id": "conv_123",
  "persona": "nirvana",
  "capability": "videoGeneration",
  "prompt": "Сделай кинематографичный тизер",
  "attachments": [],
  "parameters": {}
}
```

Шлюз возвращает внутренний `job_id`. Результат появляется в том же чате как
inline-сообщение генерации.

## Контекст и персоны

Шлюз не является источником истины для истории чата. История и состояние
беседы хранятся в продуктовой модели Wesi AI. На зарубежный сервер уходит
только сформированный пакет контекста, необходимый для конкретной операции.

При смене модели:

- идентификатор беседы не меняется;
- persona не меняется;
- rolling summary не теряется;
- активные артефакты остаются связанными с беседой;
- пользователь не обязан повторять задачу.

## Маршрутизация

Шлюз выбирает внешнюю модель по:

- способности;
- выбранной персоне;
- доступности провайдера;
- стоимости;
- ограничениям размера и длительности;
- требованиям приватности;
- типу вложений;
- необходимости продолжить существующую генерацию.

Приложение не должно содержать жёсткий список внешних моделей. Оно получает
список доступных способностей через `/v1/capabilities`.

## Передача результата

Текст возвращается потоково через SSE или совместимый streaming response.
Изображения, видео и аудио возвращаются как метаданные артефакта и
временная защищённая ссылка либо копируются в корпоративное хранилище.

Для каждого результата сохраняются:

- conversation id;
- message id;
- persona;
- capability;
- provider job id только на сервере;
- версия результата;
- MIME, размер и sha256;
- исходный prompt и безопасные параметры;
- срок жизни временной ссылки.

## Ошибки и резервирование

Шлюз возвращает стабильные внутренние коды, например:

```text
WAI_AUTH_REQUIRED
WAI_FORBIDDEN
WAI_CAPABILITY_UNAVAILABLE
WAI_PROVIDER_TIMEOUT
WAI_RATE_LIMIT
WAI_JOB_FAILED
WAI_RESULT_EXPIRED
```

Названия внешних провайдеров не должны быть обязательной частью клиентской
логики. Шлюз может переключить модель, сохранив тот же контракт.

## Критерии готовности

- сетевой дамп приложения не содержит ключей AI-провайдеров;
- блокировка одного внешнего AI-домена на устройстве не ломает Wesi AI,
  поскольку устройство обращается только к `ai.wesi-inc.ru`;
- смена внешней модели выполняется на сервере без обновления APK/Windows;
- текст, изображения, видео и аудио проходят через единый gateway;
- токен сотрудника проверяется на каждом запросе;
- генерации продолжают отображаться в исходном чате;
- шлюз умеет отменять и восстанавливать долгие jobs;
- российский сервер не хранит секреты внешних AI-провайдеров.
