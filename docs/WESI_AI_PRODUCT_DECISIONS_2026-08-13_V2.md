# Wesi AI — дополнительные решения владельца v2

> Дата: 13 августа 2026. Этот файл уточняет более ранние решения и имеет приоритет при конфликте.

## 1. Перенос между устройствами

Перенос чатов и памяти между двумя своими устройствами должен выполняться напрямую по локальной сети / Wi-Fi.

Сценарий:
1. сотрудник входит в WesiOS на обоих устройствах;
2. оба устройства подключены к одной локальной сети;
3. исходное устройство запускает передачу Wesi AI;
4. принимающее устройство подтверждает её;
5. устройства устанавливают защищённое локальное соединение и передают выбранные данные напрямую device-to-device.

Можно передавать отдельные чаты, набор чатов, все чаты, общую персональную память, память Зейна, память Нирваны и связанные локальные вложения/артефакты.

Основной сервер Wesi может подтверждать личность пользователя и устройства и помогать короткоживущим handshake/token, но полное содержимое чатов при таком переносе через сервер не маршрутизируется. Зарубежный AI Relay в переносе чатов не участвует.

Cloud-save важных разговоров остаётся отдельной backup-функцией, но для переноса между двумя доступными устройствами облако не требуется.

## 2. Wesi AI Максимальный

Подтверждён вариант, при котором `Wesi AI Максимальный` задаёт максимальную планку качества и доступного вычислительного бюджета, но основной сервер не обязан использовать самый тяжёлый внутренний маршрут для каждого простого сообщения.

Для коротких бытовых реплик сервер может использовать более лёгкий маршрут, если сохраняются качество и характер persona. Для сложных задач уровень `Максимальный` разрешает наиболее сильный доступный внутренний маршрут, больший reasoning/context budget и дополнительные проверки.

Пользовательские уровни остаются общими для Зейна и Нирваны:

```text
Wesi AI Быстрый
Wesi AI Pro
Wesi AI Максимальный
```

## 3. Выбор persona и handoff

Обычный разговор начинается с того, что сотрудник сам выбирает Зейна или Нирвану.

Если запрос по смыслу лучше соответствует другой persona, текущая persona предлагает переключение в своём характере. Переключение выполняется только после согласия пользователя.

При согласии основной сервер формирует handoff package и передаёт новой persona необходимый контекст, поэтому пользователь не повторяет задачу.

Handoff включает цель, текущий запрос, принятые решения, ограничения, summary, релевантные сообщения, нужные memories, ссылки на объекты WesiOS, вложения/артефакты, pending actions и открытые вопросы. Нерелевантная история не передаётся без необходимости.

## 4. Автоматический переход в Lobby

Если ситуация по контексту требует одновременно Зейна и Нирвану, разговор может перейти в Lobby.

Примеры:
- пользователь просит Зейна позвать Нирвану;
- пользователь просит Нирвану позвать Зейна;
- задача одновременно требует технической и творческой работы;
- текущая persona понимает, что качественный результат требует обеих сторон.

В Lobby Зейн и Нирвана остаются отдельными личностями и отдельными авторами сообщений, знают общий рабочий контекст и могут отвечать пользователю и друг другу.

Сохраняются два режима:
- `Оба отвечают`;
- `Умное Lobby`, где основной сервер определяет ограниченный план реплик.

Главное правило: по умолчанию пользователь сначала сам выбирает, кому писать; handoff или Lobby появляются уже по ходу работы.

## 5. Proactive insights

Ранее принятое правило остаётся: proactive Wesi AI настраивается для каждого сотрудника.

Если insight явно относится к технической/финансовой/аналитической части, его обычно ведёт Зейн. Творческие/media-сигналы обычно ведёт Нирвана. Если реально требуются оба, основной сервер может использовать Lobby, но не должен создавать лишний шум.

## 6. Приоритет

При конфликте это более позднее прямое решение владельца имеет приоритет. При следующей полной ревизии правила необходимо встроить непосредственно в `docs/WESI_AI_SPEC.md`, чтобы основной документ снова стал единым непротиворечивым источником истины.
