# Как закрыть репозиторий

## Коротко

**Своя машина сборки не нужна.** Я думал иначе, пока не посчитал; цифры ниже.
Всё, что мешало закрыть репозиторий, уже исправлено в коде. Осталось одно
действие, и сделать его могу только вы:

> **Settings → внизу Danger Zone → Change repository visibility → Make private**

Дальше в приложении один раз войти в GitHub (Настройки → Ключи → «Войти в
GitHub»), иначе перестанут работать обновление и загрузка движков прогноза.
Это одно подтверждение в браузере, вводить и хранить ничего не нужно.

---

## Почему сборка на своём компьютере не нужна

Замерено по прогону №555, а не прикинуто:

| | Идёт | Списывается с квоты |
|---|---|---|
| Windows | 5 мин 49 с | **12 мин** — у Windows двойной тариф |
| Android | 7 мин 52 с | **8 мин** |
| **Сборка целиком** | | **20 мин** |

Бесплатно даётся 2000 минут в месяц — это **100 полных сборок**. Для одного
человека это не потолок, а запас.

Настоящий лимит был другой:

| | |
|---|---|
| Артефакты за прогон | 14,8 МБ (Windows) + 24,3 МБ (Android) = **39 МБ** |
| Хранилище закрытого репозитория | **500 МБ** |
| Срок хранения стоял | 90 дней (значение по умолчанию, нигде не задано) |
| Хватило бы на | **12 сборок** |

Тринадцатая упала бы на выгрузке артефакта — уже после того, как всё
собралось. Вот что уперлось бы первым, а вовсе не минуты.

**Исправлено:** срок хранения задан явно — 1 день в `build.yml`, 7 дней в
`release-app.yml`. Настоящий канал раздачи — GitHub Release, а ассеты релизов
в лимит хранилища не входят вовсе. Артефакты в `build.yml` — это просто
доказательство, что код собрался; дольше суток они никому не нужны.

При таком сроке даже пять сборок в день — это 195 МБ вместо 500. Запас
четырёхкратный.

## Что ещё было бы сломано и уже починено

**Загрузка движков прогноза.** `EngineInstallService` качал Prophet и SARIMAX
по прямой ссылке на релиз — без токена. У закрытого репозитория такая ссылка
отдаёт 404 всем, включая само приложение. Проверил бы это только тот, кто
после закрытия репозитория пошёл бы ставить движок, — то есть никто, пока не
понадобится.

Теперь оба скачивания (обновление приложения и движки) идут через общий
`GitHubReleaseDownload`: сначала прямая ссылка — она быстрее, отдаёт CDN, —
при отказе обращение к API с токеном. Один и тот же код работает и на
открытом репозитории, и на закрытом; переключать ничего не надо.

**Молчаливый отказ в интерфейсе.** Любая неудача загрузки движка, кроме «не
Windows», показывалась как «Не установлен». Человек нажимал «Скачать», ничего
не происходило, надпись возвращалась к прежней. Теперь причина написана
рядом с кнопкой, и «нужен вход в GitHub» отделён от «нет связи» — потому что
первое чинится в одно действие, а кнопка «Повторить» на нём бесполезна
сколько её ни жми.

**Обновление приложения** менять не пришлось: `GitHubAuthService` изначально
писался под закрытый репозиторий (это прямо сказано в его описании), и без
входа он честно сообщает код W101, а не молчит.

## Если минут когда-нибудь станет мало

Тогда — и только тогда — есть запасной путь: собирать на своём компьютере.
Свои машины сборки бесплатны и на закрытых репозиториях.

Место сборки вынесено в переменные, менять рабочие процессы не нужно:

```yaml
runs-on: ${{ vars.RUNNER_WINDOWS || 'windows-2022' }}
```

Переменная не задана — всё идёт на GitHub, как сейчас.

### Настройка

1. **Взять код регистрации.** Репозиторий → Settings → Actions → Runners →
   New self-hosted runner → Windows. Нужен только код из строки
   `./config.cmd --token XXXXXXXX`. Он живёт час и ничего, кроме подключения
   раннера, не позволяет.

2. **Запустить скрипт** в PowerShell **от имени администратора**:

   ```powershell
   .\tools\setup-runner.ps1 -Token ВАШ_КОД
   ```

   Скрипт сам доставит чего не хватает (Git, Flutter, инструменты C++),
   скачает раннер последней версии, подключит под меткой `wesios-laptop` и
   поставит службой — чтобы работал после перезагрузки.

3. **Включить.** Settings → Secrets and variables → Actions → Variables →
   New repository variable:

   ```
   RUNNER_WINDOWS = wesios-laptop
   ```

Переносить стоит именно Windows: он идёт по двойному тарифу. Android оставьте
на GitHub — 8 минут на сборку, это 250 сборок в месяц.

### Что важно знать

**Свой раннер и открытый репозиторий несовместимы.** Это предупреждение
самого GitHub: на открытом репозитории любой может прислать изменение, и его
код выполнится **на вашем компьютере**. Раннер включать только после того,
как репозиторий закрыт.

**Ноутбук выключен — сборка ждёт в очереди.** Не хотите ждать — сотрите
переменную `RUNNER_WINDOWS`, и сборка снова уйдёт на GitHub. Раннер при этом
трогать не нужно.

| Симптом | Причина |
|---|---|
| `config.cmd` ругается на код | Код просрочен, ему час. Возьмите новый. |
| Сборка висит в очереди | Раннер не запущен: `Get-Service actions.runner.*` |
| Падает на CMake | Нет нагрузки C++ в Build Tools — запустите скрипт заново |
| Раннер серый (Offline) | `Start-Service actions.runner.*` |

Снять раннер совсем:

```powershell
cd C:\actions-runner
.\config.cmd remove --token НОВЫЙ_КОД
```

## Чего я не могу сделать за вас

Честно, чтобы не ждали зря:

- **закрыть репозиторий** — это действие в настройках GitHub, доступа к ним у
  меня нет, только к коду;
- **поставить раннер на ваш ноутбук** — я работаю в отдельном контейнере в
  облаке и к вашему компьютеру не подключаюсь (об этом уже спрашивали);
- **войти в GitHub внутри приложения** — вход подтверждается в вашем браузере,
  в этом весь смысл device flow: ни я, ни само приложение пароля не видят.

Всё остальное — сроки хранения, скачивание по токену, сообщения об ошибках,
скрипт настройки раннера — уже сделано и лежит в этой ветке.
