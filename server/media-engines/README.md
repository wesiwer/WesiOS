# Wesi AI Media Engines

WesiOS itself contains no image/music/video model weights. Optional engines are
published as immutable ZIP packages under the Wesi artifact endpoint and are
installed by the application only when the user asks for them.

## Public layout

With the default Wesi artifact endpoint the client reads:

`https://api.wesi-inc.ru/artifacts/media-engines/manifest.json`

The manifest contains relative package paths, so storage can move without an
application release. Packages normally live under:

`media-engines/packages/<kind>/<id>/<version>/<id>-<version>.zip`

The `publish_media_package.py` utility computes the exact byte size and SHA-256
from the prepared ZIP. Never hand-write production hashes.

## Package contract

A package is a ZIP containing all runtime dependencies it needs and a launcher
named by `launcher` in the manifest. WesiOS does not run `pip install`, npm,
or arbitrary dependency installation after download.

The launcher reads one JSON object from stdin and writes one JSON object as the
first stdout line. It must not print logs before that first JSON line.

Request example:

```json
{"prompt":"night city in rain","aspectRatio":"16:9"}
```

Minimum successful response contract for engine builders:

```json
{"ok":true,"output":"generated/result.png","mimeType":"image/png"}
```

`output` must be a relative path inside the installed engine directory. A
runtime may place diagnostics after the first JSON line, but WesiOS ignores
those diagnostics.

## Publishing

Example only (paths and requirements must match a package that was actually
tested):

```bash
python3 server/media-engines/publish_media_package.py \
  --kind image \
  --id wesi-image-qwen \
  --name 'Wesi Image / Qwen' \
  --version 2026.08.14 \
  --archive /staging/wesi-image-qwen-2026.08.14.zip \
  --license Apache-2.0 \
  --license-url https://huggingface.co/Qwen/Qwen-Image/blob/main/LICENSE \
  --launcher launcher.bat \
  --min-ram-gb 16 \
  --recommended-vram-gb 12 \
  --platform windows
```

The destination root defaults to `/srv/wesi-artifacts`; set
`WESI_ARTIFACTS_DIR` when the production Wesi artifact directory is different.

## Safety rules

- Do not commit model weights to this repository.
- Do not publish a package before its upstream license is reviewed.
- Do not publish a ZIP assembled from mutable/unpinned sources.
- Production packages require a real SHA-256 and byte count generated by the
  publisher.
- The client deletes packages that fail size or SHA-256 verification.
- Image/video/music cloud generation is disabled in Relay by default; enabling
  it requires the explicit `WESI_ENABLE_PAID_MEDIA=true` operator opt-in.

## Initial candidates

The repository intentionally does not pin these into the production manifest
until a Wesi runtime package is built and tested on supported hardware.

- Image: Qwen-Image (Apache-2.0).
- Music: ACE-Step 1.5 (MIT in its published model repository).
- Video: Wan2.2 TI2V-5B (Apache-2.0).

These upstream repositories are much larger than the current small Relay VPS,
so model distribution storage must be provisioned separately from the text
Relay before the packages are mirrored.
